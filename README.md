# Task Management SaaS

A multi-tenant task management app. Each organization gets its own projects, tasks and users, and one organization can never see or change another's data.

## Features

- Register an organization together with its first user, who becomes its administrator.
- Log in with email and password and receive a stateless JWT.
- Create, edit and delete projects.
- Create, edit and delete tasks, move them between statuses and filter by status. Each task belongs to a project and has a priority.
- Dashboard with task counts by status.
- The API also supports assigning tasks, a "my tasks" endpoint and due dates, which the UI does not use yet.
- Roles enforced by the API: `ADMIN` and `MEMBER` can write, `VIEWER` is read-only, and only `ADMIN` can delete projects.

## Tech stack

- **Backend:** Java 17, Spring Boot 3.2, Spring Security (stateless JWT), Spring Data JPA / Hibernate
- **Database:** PostgreSQL
- **Frontend:** React 18, React Router, axios, Tailwind CSS (Create React App)
- **Tests:** JUnit 5 and MockMvc on an in-memory H2 database

## Prerequisites

- JDK 17 to 21 (the Gradle wrapper is included)
- Node.js and npm
- PostgreSQL, either your own or the one in `docker-compose.yml` (needs Docker)

## Getting started

1. Create your local configuration (PowerShell: use `Copy-Item` instead of `cp`):

   ```bash
   cp .env.example .env
   ```

   Edit `.env` and set `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD` and `JWT_SECRET`. Generate the secret with `openssl rand -base64 48`. `.env` is gitignored.

2. Start PostgreSQL. To use the bundled one:

   ```bash
   docker compose up -d
   ```

   If port 5432 is already taken, set `POSTGRES_PORT` in `.env` to another port. If you use your own PostgreSQL, create the database and user from `.env` and set `POSTGRES_HOST` / `POSTGRES_PORT` if they are not the defaults.

3. Start the API on http://localhost:8080. Tables are created automatically on first start:

   ```bash
   ./gradlew bootRun
   ```

4. Start the frontend on http://localhost:3000:

   ```bash
   cd frontend
   npm install
   npm start
   ```

5. Open http://localhost:3000, choose **Register**, and create an organization.

## Configuration

All settings come from environment variables or `.env`.

| Variable | Required | Purpose |
|---|---|---|
| `POSTGRES_DB` | yes | Database name |
| `POSTGRES_USER` | yes | Database user |
| `POSTGRES_PASSWORD` | yes | Database password |
| `JWT_SECRET` | yes | Signing key for tokens (at least 32 characters) |
| `POSTGRES_HOST` | no | Defaults to `localhost` |
| `POSTGRES_PORT` | no | Defaults to `5432` |
| `JWT_EXPIRATION_MS` | no | Token lifetime, defaults to 24 hours |
| `CORS_ALLOWED_ORIGINS` | no | Comma-separated browser origins, defaults to `http://localhost:3000` |

## Tests

```bash
./gradlew test
```

The tests need no database. They register two separate organizations through the real API and check that one cannot read, create, change, delete or assign anything in the other, that password hashes are never returned, that roles are enforced, and that bad credentials and tokens get a 401.

## API

All routes except `/api/auth/**` need an `Authorization: Bearer <token>` header. Errors are returned as `{ "message": "..." }`.

| Method | Path | Description |
|---|---|---|
| `POST` | `/api/auth/register` | Create an organization and its first (admin) user |
| `POST` | `/api/auth/login` | Log in and receive a token |
| `GET` | `/api/projects` | List the organization's projects |
| `GET` / `POST` | `/api/organizations/{orgId}/projects` | List or create projects (`orgId` must be your own) |
| `PUT` / `DELETE` | `/api/projects/{id}` | Update a project, or delete it and its tasks (admin) |
| `GET` | `/api/tasks` | List the organization's tasks |
| `GET` | `/api/tasks/my-tasks` | Tasks assigned to you |
| `POST` | `/api/tasks` | Create a task |
| `PUT` | `/api/tasks/{id}` | Partial update: only the fields you send change |
| `DELETE` | `/api/tasks/{id}` | Delete a task |

## How multi-tenancy is enforced

The organization is taken from the authenticated user, which is loaded from the database on every request. It is never read from the request. Every project and task lookup is scoped to that organization, so a resource belonging to another tenant is reported as not found, which does not reveal that it exists. Task assignees must belong to the same organization.

## Notes and limitations

This is a demo project, not production-ready.

- The database schema is generated by Hibernate (`ddl-auto=update`). A real deployment should use migrations such as Flyway.
- The token is kept in `localStorage`, which is exposed to any cross-site scripting bug. There are no refresh tokens, email verification or password reset.
- There is no invitation flow, so every registration creates a new organization. The Team and Settings pages are placeholders, and the `MEMBER` and `VIEWER` roles are exercised by the tests only.
- Task comments exist in the data model but have no API or UI yet.
